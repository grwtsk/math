# HS-95 lane 05 · Finite-graph capacity of the native read language

Local source attribution is grwtsk contributors. Formalization and checking assistance by OpenAI Codex.

## Statement and consumer

For every finite type V, every labeled graph on V with one scanned bit per edge, and every root r in V, suppose a word labels a path from r if and only if it is a successful read prefix of the pinned blank-start Riemann95 machine. Then the cardinality of V is at least **257**. The statement permits arbitrary edge relations, including nondeterministic ones. The proof consumes the existing [exact configuration graph](Riemann95ConfigurationLanguage.lean) and the [labeled path interface](../../DynamicalSystemsAndErgodicTheory/ExactSoficLanguageCover.lean).

The conclusion is `rooted_prefix_graph_capacity` in [Riemann95PrefixGraphCapacity.lean](Riemann95PrefixGraphCapacity.lean). In fact, `small_graph_admits_spurious_word` applies to every rooted candidate with at most 256 vertices that accepts the observed 263-bit word. It returns an accepted shorter word that fails the native read-prefix test. If the candidate omits the observed word, the same observation already witnesses missing coverage. This is a diagnostic for the admissible layer of the HS graph sandwich before claiming exact prefix coverage.

## Argument and finite controls

The native configuration fixes the next scanned bit and, when the step succeeds, fixes the next configuration. Induction on paths proves `native_prefix_forced`. Given two admitted native words from blank, the shorter must equal the prefix of its length of the longer.

Choose a candidate path for the 263-bit word. It has 257 vertex visits at positions 0 through 256 inclusive. At most 256 vertices force two equal visit vertices at positions i < j ≤ 256. `shortened_path` joins the prefix through i to the suffix starting at j with the same endpoint. The resulting word has length 263−p where p = j−i. Its last seven bits remain 0100111, the tail of the original word. The corresponding native prefix of length 263−p ends with a different seven-bit block, for every p from 1 through 256. Thus the candidate accepts a spurious word. The repeated vertex is a witness in the candidate graph. The contradiction comes from trying to lift the shortened path back to the source.

The 263 bits were generated by a separate sparse absolute-tape evaluator of the literal table. `bootRead263_native` uses kernel evaluation of the native executor to verify the reads with both half tapes retained. `bootRead263_length` fixes the length and `bootRead263_tail_separates` checks the 256 finite comparisons. The same witness covers a graph with one state that admits every word, and the 95-control graph projection.

## Scope and next obligation

The bound is for exact blank-rooted successful read prefixes at native-step granularity. A complete prefix-and-terminal presentation includes this requirement. Clocks or history used to select admissible edges contribute to the total vertex state of a static presentation. A larger finite presentation still needs a proof that every admitted extension can be lifted from the current reachable tape. The earlier configuration-language proof gives bidirectional paths and terminality when the full tape is carried. A projected 95-position clock wrap also needs a full-state return witness before it may be used as a source periodic path. [Exact configuration and periodic controls](Riemann95ConfigurationLanguage.md) · [Prime-machine transport](https://github.com/grwtsk/math/issues/1821)

```text
Pinned table + native tape executor → admitted 263-read prefix
Native deterministic steps → forced word at each prefix length
Candidate capacity ≤ 256 + observed path → shorter admitted word
Kernel-checked tail separation → false lift from the candidate to the source
Full-state path lifting + terminal agreement → remaining runtime obligation
```
