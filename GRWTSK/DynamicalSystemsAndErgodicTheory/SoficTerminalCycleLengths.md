# Terminal-compatible cycles and accepted lengths

[Lean source](SoficTerminalCycleLengths.lean), SHA-256 `37aeecf0bbff8799eb14a2a36708694d2ae60dc19758053166cbe73edeaead26`, extends [terminal trimming](SoficTerminalPrefixTrim.lean), blob `db3a953aa25c99429af8d9c8568ab956c6b4490c`. The motivating source is the [native Riemann95 configuration language](../Combinatorics/GraphTheory/Riemann95ConfigurationLanguage.lean), whose root is the native blank configuration and whose terminal mark is absence of a native instruction. The dispatch pins Cryptids at `3647718b5df22e1a61462dec0376bd204526285a`.

Fix a path from the root to a cycle vertex, a loop there, and a path from the vertex to a marked terminal. Concatenating the entry path, k copies of the loop, and the terminal path gives accepted lengths a+kL for every natural k, where a is the combined entry and exit length and L is the loop length. Any bound on accepted lengths excludes such a loop for L>0, including L=95. This extends the earlier singleton exclusion to arbitrary bounded terminal languages and does not require finitely many graph vertices. The checked one-vertex marked full shift has a 95-step return and accepts a word of every length. Its graph return cannot certify an exact presentation of a bounded native terminal language.

The proposed HS graph still owes the direction from its terminal paths to native terminal paths. A bound on native terminal lengths transfers only with that direction established. The result does not concern cycles outside the reachable, terminal-compatible part of the graph. The offset chat's infinite-prefix lasso rigidity addresses the separate live trace question.
