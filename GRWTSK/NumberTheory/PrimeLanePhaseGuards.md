# Exact phase guards for the prime-lane carrier

[Lean source](PrimeLanePhaseGuards.lean), SHA-256 `42b0d8c1b710cba1d84ff82297242eae2f11b8c12ea0ff4dd3f577cc25fa63ed`, extends [PrimeLaneMultiplexing](PrimeLaneMultiplexing.lean), Git blob `4088e71e0bb98529066269cf9d761960c4233a34`. The lane coordinate indexes the same ordered prime labels, with each control state assigned to one lane in a fixed frame. The decoder must recover that state from any of its consecutive acceptable phases. Guards fit inside the frame, and the observer reads the lane and phase. The source transition table and tape payload are external to this count. The dispatch pins Cryptids at `3647718b5df22e1a61462dec0376bd204526285a`.

Every state and offset pair produces a slot. A collision forces the same state by decoder correctness and then the same offset by cancellation. Thus states times guard width cannot exceed lanes times phases. For positive width and a frame made of whole blocks, the bound is sufficient. Apply the existing row-major encoder to the lane and block indices, then use the corresponding interval of phases. Integer division by the guard width recovers the original block at every acceptable phase. With five lanes and two acceptable phases per control, 95 controls require at least 38 frame phases, and 38 suffice. The earlier five-by-nineteen layout is a checked falsification control when the two-phase guarantee is imposed.

The result supplies a condition on a physical scheduler and its readout. The physical system must establish the guard model and implement the specified decoding and source transition return.
