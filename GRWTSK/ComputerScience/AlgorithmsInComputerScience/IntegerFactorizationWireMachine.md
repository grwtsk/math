# Writing the canonical factorization to a machine output

Local construction by grwtsk contributors. The mathematical consumer is the final stage of a fixed deterministic complete-factorization machine. The producer emits each count or row bit by pushing it on the corresponding stack. The finalizer accepts the two resulting reverse-order buffers and any binary scratch stack. It uses the precise count word and row layout of the canonical certificate. [Lean declarations](IntegerFactorizationWireMachine.lean) · [Wire specification](../../NumberTheory/IntegerFactorizationCertificate.lean) · [Machine assembly issue](https://github.com/grwtsk/math/issues/1858).

## Program and cost

There are four binary stacks, three labels, and a three-value control register. The rows phase takes the top bit from the row buffer and pushes it onto the output. On reaching the end, the count phase does the same with the count buffer. Placing the count last on the front of the output gives the required header before the rows. The final phase discards each remaining scratch bit, reads the empty stack, and halts.

| Execution | Mathlib TM2 macro-steps | Executed statement nodes |
| --- | ---: | ---: |
| Each count or row bit | 1 | 4, comprising pop, branch, push, goto |
| Each discarded scratch bit | 1 | 3, comprising pop, branch, goto |
| Each of two phase changes | 1 | 3, comprising empty pop, branch, goto |
| Halt | 1 | 3, comprising empty pop, branch, halt |

For $L$ output bits and $G$ scratch bits, `transfer_exact` gives $L+G+3$ transitions to the full Mathlib halt configuration. The control register is empty, every work stack is empty, and the output contains exactly the forward count word followed by the forward row sequence. `transfer_dispatches` counts $4L+3G+9$ statement nodes on that execution. The proof evaluates only the branch actually taken. The zero-length case costs three macro-steps and nine statement nodes. An arbitrary nonempty scratch buffer increases both counts even when it contributes nothing to the observable output.

For $b=1+\lfloor\log_2N\rfloor$ and $r$ distinct prime bases, the wire has $L=b(1+2r)$ bits. The canonical arithmetic bound $r\le b-1$ gives at most $b(2b-1)+G+3$ macro-steps. Every stack symbol in the finalizer is a bit and every step inspects a bounded number of stack heads. The native statement count and the macro-step count are both exact. The constant relating either count to a particular primitive multitape transition table depends on that table. ## Return to the caller

`linked` builds a single Mathlib machine from caller code and the concrete suffix. Its disjoint indices preserve the caller's own alphabet, labels, control, and work stacks. The caller may jump to the finalizer once its private work stacks are empty. `step_lift` proves exact preservation of a local transition in the linked program. The proof first inducts over the statement syntax, including branch, peek, pop, and push. It then iterates the resulting step correspondence on full configurations. `finish_after` charges the caller's actual run up to the handoff and appends the verified suffix. The known part of the finish contract therefore includes count/body concatenation, bit order, scratch erasure, output, and halt. Constructing the prime powers and emitting their individual fixed-width bits onto the two work buffers are obligations of the producer. A caller must bound its discarded $G$ as well as its execution time.

Rudich and Rousseau’s separate `run_divmodSeg` supplies both outputs of binary long division. The compiled local adaptation takes bounded-width binary arrays for the residual and positive divisor, writes the quotient and remainder to separate arrays, and clears its widened divisor copy. On a proper exact split, its quotient is the strictly smaller cofactor and its remainder is zero. The finite bit-stack adapter halts with a single encoded heap on its output stack. Its decoder reads both binary banks and its polynomial bound charges every simulated register access, both transfers and halt. The caller must connect the least-factor output to the divisor bank, use the returned quotient for the next iteration, group equal primes and push the count and rows in the finalizer’s fixed-width layout. These interfaces use different encodings, and their conversion and cleanup costs belong to the complete caller.
