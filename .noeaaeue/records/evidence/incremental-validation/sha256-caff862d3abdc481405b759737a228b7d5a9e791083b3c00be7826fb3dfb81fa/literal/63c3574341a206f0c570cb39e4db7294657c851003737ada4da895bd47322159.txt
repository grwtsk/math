# GRWTSK mathematics

A Lean library of mathematical definitions, proofs, counterexamples and explicit open problems. The formal sources live in `GRWTSK/`, with `GRWTSK.lean` as the library entry point.

Build with the pinned Lean and Mathlib dependencies:

```sh
lake build --wfail
```

Lake builds are incremental. Run the proof validator to check all active library
modules with trust zero, fatal warnings, and the owned-declaration axiom audit:

```sh
python3 -B .noeaaeue/scripts/check_math_trust.py
```

The validator reuses verified compilation and native audit results for unchanged
inputs, rebuilding changed modules and their import dependents. It checks current
source membership and bytes, dependency objects, compiler, flags, audit policy,
and the complete declaration census before accepting a run. Receipts distinguish
fresh work from reused checks. The disposable cache lives under the ignored
`.noeaaeue/.local/` directory; historical evidence is retained separately.
Each reusable proof check names an immutable successful origin receipt by its
digest, size, and validation attempt. Missing or changed origins force replay.
WSC integration retains those origins and their source/evidence bindings
separately from the disposable execution cache; cache reuse does not establish
arbitrary filesystem read confinement.

Request a full cold project replay explicitly:

```sh
python3 -B .noeaaeue/scripts/check_math_trust.py --cold
```

Selected validators using the shared incremental runner also accept `--cold`.
Cold project replay continues to reuse the pinned external dependency objects;
it freshly compiles and audits every selected project module.

The committed `lean-toolchain` and `lake-manifest.json` pin Lean 4.33.0 and Mathlib revision `db584cd6d46c92f209a44c0f1c829460d327499d`.

Browse the [mathematical subjects](docs/index.md), follow the [least-prime tutorial](docs/start/least-prime.md), or consult the [selected result catalog](docs/reference/results.md). Object guides state exact hypotheses and distinguish formal proofs, conditional results, written arguments, historical checks and open obligations. A successful build does not settle the Riemann hypothesis or the open Möbius cross-energy bound.
