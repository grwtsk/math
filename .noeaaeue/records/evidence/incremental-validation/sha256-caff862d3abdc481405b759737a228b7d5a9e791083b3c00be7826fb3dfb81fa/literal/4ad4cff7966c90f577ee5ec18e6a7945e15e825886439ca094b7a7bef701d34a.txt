NOE-MATH-WSC-CODEX / 0.1.0 — Data-Only Workspace-Capsule Foliation and Fixed-Point Review Worker
Status
This is a source-bound implementation specification for a Codex worker operating primarily in grwtsk/math/.noeaaeue/. It defines an iterative data-engineering and review process for interpreting NOE-MATH-WSC / 0.2.0 — Source-Bound Mathematical Workspace Capsule, Proof Graph, Moment, and Runtime Architecture within the repository-local capsule.
The review roles below are simulated internal review lenses. They do not imply that outside experts were contacted, that an independent audit occurred, or that any architecture was adopted before the corresponding source-bound records and repository changes exist.
This worker is data-only. It may author, normalize, validate, materialize, and review declarative data. It must not implement or activate the runtime.

Primary instruction
Transform the current post-cleanup .noeaaeue/ tree into an additive, source-bound workspace capsule whose authored declarations, compatibility mappings, typed graph materializations, evidence records, research-package records, moment records, verification data, and retention rules maximally interpret NOE-MATH-WSC / 0.2.0 at the selected repository scope.
Perform the work in repeated outer cycles. Within every outer cycle, perform an implementation tranche followed by repeated review-and-fix passes until the tranche has no open findings. Then recompute the full-corpus interpretation backlog and begin the next outer cycle. Continue until the data capsule reaches the fixed-point conditions defined below.
Do not move, delete, rewrite, refresh, or reinterpret any baseline historical bytes. Normalize by source-bound copy and typed reference. Do not create authority through placement, digesting, compilation exit status, documentation labels, or graph reachability.

Definition of maximal foliation
“Foliation” means decomposing mixed repository material into independently addressable, source-bound typed facts without destroying or rewriting its original occurrence.
At minimum, the capsule must separate these dimensions whenever the source supports them:
1. Logical identity.
2. Semantic identity.
3. Content identity.
4. Source-occurrence identity.
5. Environment identity.
6. Attempt identity.
7. Evidence scope and evidence grade.
8. Execution state and decision outcome.
9. Freshness and invalidation state.
10. Public-entrypoint and root-reachability state.
11. Reconstruction state and formal-correctness state.
12. Retention class and write policy.
13. Graph node kind and edge kind.
14. Legacy compatibility locator and canonical identity.
15. Explicit nonclaims and unresolved premises.
The capsule is maximally foliated at the selected scope only when all of the following are true:
- Every tracked baseline leaf occurrence under .noeaaeue/ is present in the baseline inventory and compatibility map.
- Every parseable embedded record that has an identity distinct from its container has a source locator such as a JSON Pointer, JSONL line, source span, or member path.
- Every NOE-MATH-WSC / 0.2.0 requirement has a coverage row with one of: implemented_data, represented_by_pinned_schema, not_applicable_to_selected_sources, out_of_scope_by_user_directive, or blocked.
- No requirement remains unclassified, implicitly omitted, or marked with an unexplained generic unknown.
- No resolvable legacy object remains in unknown_requiring_review.
- Every reference resolves or has a recorded inaccessible-source or blocker record.
- Every generated projection is reproducible from declared finite reads.
- A complete full-corpus review produces no new object kind, edge kind, classification, source binding, issue, or unmet data requirement.
- A second clean full-corpus pass from a clean checkout produces the same digests and again produces no findings.
A blocked requirement prevents a claim of maximal closure. The worker must report blocked, preserve completed work, and state the exact missing capability or source. It must not guess to obtain a zero-issue result.

Revision correction and incrementality
For each canonical claim or artifact, retain declared reads and semantic dependencies. When the selected source snapshot changes, compute:
directly changed objects = objects whose declared reads changed
affected closure         = dependency closure of directly changed objects plus withdrawals
Then:
1. Append a correction record naming before snapshot, after snapshot, withdrawals, directly changed objects, and affected closure.
2. Reopen affected projections without deleting archived evidence.
3. Retain unaffected evidence only through a revision-locality certificate covering every declared read.
4. Invalidate the locality certificate if a dependency schema or read-set declaration changes.
5. Bind every new attempt and receipt to the current selected snapshot.
Timestamps and file-level heuristics may accelerate discovery but are not the semantic invalidation rule.

Iterative execution algorithm
Use the following outer fixed-point algorithm:
cycle := 0
repeat
  freeze exact repository and working-tree observations
  compare with prior selected snapshot
  append correction records for changed sources
  rebuild the deterministic architecture-coverage backlog

  if backlog is empty then
    run the complete review suite from a clean checkout
    rerun the complete review suite from a second clean materialization
    if both runs have no findings and identical declared digests then
      emit final data-closure receipt and stop
    end if
  end if

  select the next deterministic, bounded tranche
  implement only that tranche

  repeat
    run Review A: custody and mutation
    fix every Review A finding

    run Review B: schema, identity, and retention
    fix every Review B finding

    run Review C: formal semantics and evidence authority
    fix every Review C finding

    run Review D: graph determinism, reconstruction, and adversarial controls
    fix every Review D finding

    rerun Reviews A through D from the beginning
  until all four reviews return zero open findings

  append cycle receipts, review records, and nonclaims
  promote only digest-named deterministic outputs
  commit the closed cycle without rewriting prior cycle records
  cycle := cycle + 1
forever
A review must examine the current bytes independently of the implementer’s prior summary. A fix invalidates prior review closure and requires the entire review sequence to restart.
Deterministic tranche selection
Select work from the architecture-coverage backlog in this order unless a source-bound dependency requires another order:
1. Baseline and source bindings.
2. Workspace contract and registry locks.
3. Full legacy inventory and compatibility map.
4. Evidence, checks, bindings, receipts, and root-cleanup records.
5. Research packages and campaign-like compatibility directories.
6. Legacy cache/ decomposition and write sealing.
7. Scripts, tests, and tools classification.
8. Formal source, declaration, import, and public-entrypoint graph data.
9. Moment definitions, computations, reindexings, corrections, and growth bridges.
10. Revision-correction, append-only, checkpoint, and reconstruction data.
11. Query projections, architecture coverage, and final fixed-point validation.
Within a tranche, sort source occurrences by normalized repository path and stable member locator. If batching is necessary, use a deterministic path range or digest partition and record the exact boundary.
Review A — Custody, source binding, and mutation
Review A must verify:
- Exact repository revisions and working-tree observations are recorded.
- Every selected source has a digest and byte length.
- Baseline historical and compatibility bytes are unchanged.
- No protected path was moved, deleted, rewritten, or hash-refreshed.
- No source occurrence was silently replaced by a newer occurrence.
- Every generated object declares its finite reads.
- No unauthorized path was written.
- No runtime path or mutable runtime object was added.
- Concurrent edits were preserved and explicitly observed.
Any mismatch is a blocking finding.
Review B — Schema, identity, reference, and retention quality
Review B must verify:
- Every authoritative object validates against a pinned central schema or declared local extension.
- JSON Schema uses the pinned dialect and closed properties where required.
- Logical, semantic, content, occurrence, environment, and attempt identities are distinct.
- Authored declarations contain no mutable status field.
- Every reference resolves.
- IDs are unique and stable.
- Large collections use deterministic JSONL or another pinned canonical representation.
- Every object has a retention class and allowed write plane.
- No authoritative object exists only in a disposable plane.
- Legacy-map coverage is complete and nonduplicative.
- Mixed containers have member-level locators rather than false single-class collapse.
Any ambiguity that affects authority, identity, or retention is a blocking finding.
Review C — Formal semantics, evidence, and mathematical nonoverclaim
Review C must verify:
- Execution, decision, evidence, freshness, entrypoint, reconstruction, and correctness facets remain separate.
- Finite computation is not promoted to a universal theorem.
- Candidate source is not promoted to admitted or root-reachable source.
- Source parsing is not represented as elaboration.
- Focused compilation is not represented as public integration.
- Public import is not represented as independent replay.
- Exact byte reconstruction is not represented as formal correctness.
- Historical evidence is not represented as current after source drift.
- Every external-to-native transfer has a complete applicability certificate or an explicit open obligation.
- Axiom-audit records bind exact declaration and import closures.
- Negative and hostile controls retain expected rejection behavior.
- Research packages preserve stages run, stages not run, open premises, and nonclaims.
- Moment records preserve domains, constraints, signs, factor order, cutoffs, and correction terms.
- Documentation counts and graph counts are not converted into theorem counts.
Any overclaim is a blocking finding.
Review D — Determinism, reconstruction, invalidation, and hostile controls
Review D must verify:
- Two clean generations at the same inputs produce identical graph, plan, and projection digests.
- Randomized input traversal does not change canonical output.
- Generated artifacts cannot read their expected outputs or undeclared inputs.
- Generated cycles cannot ground themselves.
- Duplicate IDs, dangling edges, malformed records, path traversal, and symlink redirection are rejected.
- New authoritative writes to legacy cache/ are rejected.
- Invalid evidence promotions are rejected.
- Changed declared reads reopen exactly the affected dependency closure in test fixtures.
- Append-only fixtures reject reorder, deletion, replacement, and set-equal/non-prefix histories.
- Reindexing hostile controls detect changed signs, cutoffs, domains, weights, or factor order.
- The clean-clone graph digest matches the promoted digest.
A matching output digest without read-set confinement is not sufficient to close the reconstruction review.
