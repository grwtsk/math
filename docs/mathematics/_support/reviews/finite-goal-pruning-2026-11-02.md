# Finite goal-directed inference: a source-preserving pruning optimization

Local attribution: grwtsk contributors. Date: 2026-11-02.

## Mathematical question and consumer

The maintained [joint-premise inference](https://github.com/grwtsk/math/blob/9b46c9dc984c2a20cef7fe59984514ab038f0d58/documentation/mathematics/Combinatorics/joint-premise-inference.md)
model distinguishes AND-premises from alternative rule applications. The later
[finite closure source](../../../../GRWTSK/MathematicalLogicAndFoundations/ProofTheoryAndConstructiveMathematics/FiniteJointPremiseClosure.lean)
computes those derivable atoms for a finite list of instantiated rules and facts.
It already proves a conditional filtering theorem, but a consumer otherwise has
to supply a decidable backward-closed keep-predicate.

[This increment's source](../../../../GRWTSK/MathematicalLogicAndFoundations/ProofTheoryAndConstructiveMathematics/FiniteGoalPrunedClosure.lean)
constructs that predicate from an existing complete finite inventory, a goal
predicate and a decidable dependency *overapproximation*, and then discards
rules that contribute nothing beyond initially supplied facts.

## Exact statement

Let `A` be a type with decidable equality, and let `V` list
**every atom of A** without duplication. Let `R` and `F` be finite lists of available
joint-premise rules and initial facts. Let `G : A → Prop` be a decidable goal
predicate. Let `D : A → A → Prop` be a decidable dependency relation satisfying

```
∀ a b, RuleDepends (fun r => r ∈ R) a b → D a b.
```

Compute `K := finitePrerequisiteClosure V G D`. Keep a rule if its conclusion
belongs to `K`, keep an initial fact if it belongs to `K`, and discard a
remaining rule if its conclusion is already one of those retained facts.
The definition `decideGoalPruned` performs those finite operations and calls
the existing executable `decideFiniteClosure`. The separate constructor
`ruleDependencyEdges R` materializes each actual conclusion-to-premise edge
of the finite rule list, and `mem_ruleDependencyEdges_iff` proves the graph's
exact correspondence with `RuleDepends`. Thus
`decideSourceGoalPruned V R F G a` computes with the source-derived graph,
without asking the caller to provide or assert the edge-coverage condition.

For each `a` satisfying `G a`, the new source-level theorem
`decideGoalPruned_eq_true_iff` (under the graph-coverage hypothesis) states

```
decideGoalPruned V R F G D a = true
  ↔ Derivable (fun r => r ∈ R) (fun p => p ∈ F) a.
```

The source-derived theorem `decideSourceGoalPruned_eq_true_iff` proves
the same equivalence for `ruleDependencyEdges R`; the coverage premise is
then *proved from the given list* rather than supplied by the caller.

There is no claim for a goal outside `G`, an incomplete inventory, or rules
omitted from the input list. For an external dependency graph, coverage remains
an explicit, mathematically necessary hypothesis.

## Proof and optimization mechanism

The existing `finitePrerequisiteClosure_feasible` establishes both that the
goals lie in `K` and that `K` is closed under the supplied edges. Edge
coverage transfers that closure to every dependency generated by `R`.
Existing `finiteClosure_filter_iff` therefore gives semantic equivalence
after filtering rules and facts.

A list-map/flat-map membership argument proves
`mem_ruleDependencyEdges_iff` in both directions, without conflating a
single dependency edge with satisfaction of all the rule's premises.
The additional lemma `removeInitiallySatisfied_iff` establishes that rules
with conclusion already in the filtered facts may be removed. In an arbitrary
derivation, such a rule application can instead be replaced by the input-fact
constructor; other rule applications remain available. Equivalently, the
inductive derivability predicate of the pruned list is closed under all original
rules. Compose that lemma with the slice theorem and the already published
`mem_finiteClosure_iff` to obtain the Boolean query equivalence.

For example, with `F={0}`, rules `[]→0`, `[0]→1`, `[1]→2`,
and `[]→3`, and the goal `2`, the exact backward dependency closure
retains `0,1,2` but not `3`. The first stage removes the irrelevant
`[]→3`. The second stage removes `[]→0`, since `0` is already a fact.
Two useful rule occurrences remain from four; derivability of `2` is unchanged.

A hostile case is an omitted edge `2→1`: an asserted dependency graph
that misses it is **not** an overapproximation, so the theorem cannot
certify deletion of the premise `1`. An imprecise graph with *additional*
edges retains too much, but does not create this false-negative path.
Alternative proof routes are retained by the backward closure; an unseeded
cycle still derives nothing from no facts.

## Scope, comparative analysis and verification

This is a composition of existing elementary source constructions rather
than a claim of historical theorem-level novelty. It improves the
*mathematically justified search boundary* by making a safe finite filter
executable from a certified dependency overapproximation. It does **not**
establish asymptotic or wall-clock speedup: filtering and calculating
transitive closure have costs, and a dense overapproximation can retain
everything. The reduced list is not a minimum proof. No SAT/ETH result or
model-performance measurement follows.

The new Lean declarations are **SOURCE_PROOF_CANDIDATE**. Compilation, fresh
kernel replay and transitive axiom auditing are **NOT_RUN**. Source publication
does not inherit the unrun status of earlier modules as success; the entire
new import closure needs its own exact-source audit.

A real repository consumer still needs a checked extraction of instantiated
applications, faithful encoding of quantifier scopes, and a complete finite
atom inventory. Coverage of the edge graph for *already supplied rules* is now
a source-level theorem, not an external witness. The **source-to-instantiated-
rule extraction/refinement theorem** is the single next mathematical obligation. Runtime
evaluation, acceptance and measured retrieval benefits belong in
[Noeaaeue](https://github.com/grwtsk/noeaaeue/issues/406), not in a claim
made by this source note. The source and its exact commit/blob are tracked
through a separate, passive GitHub verification issue; no checker is dispatched.
